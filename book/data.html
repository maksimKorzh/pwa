Chapter 2

Collecting the Greeting Cards Dataset

Before we can build an application that displays greeting cards, we need something for the application to display. The interface we will build later is only one part of the project. The other important part is the dataset containing the greeting-card titles and image URLs.

Instead of manually collecting hundreds or thousands of greeting cards, we are going to create a small Python web-scraping script. The script visits the greeting-card website https://otkrytki.top/, discovers its categories and pages, extracts the greeting-card information, and saves everything into a CSV file.

The original website and the dataset are in Russian. The application that we build in the book will have an English user interface, but the collected dataset remains Russian. This distinction is important because the application will later search the Russian titles using Russian keywords, even though the category names displayed to the user will be translated into English.

The Project Structure

We are going to keep the scraping code and the resulting dataset inside a data directory. At this stage, our project has a very small structure:

index.html
data/
    greetcards.py
    greetcards.csv

The index.html file will eventually become the main application. The data/greetcards.py file is our scraper. It is responsible for collecting the data. The data/greetcards.csv file is the resulting dataset that the browser application will later load.

This separation is useful because the scraper and the application have different jobs. Python runs during the data-collection stage, while HTML, CSS, and JavaScript run in the browser when the user opens the application.

What Are We Scraping?

Web scraping means automatically reading information from a web page instead of manually copying it. A normal user opens a website in a browser and looks at the page visually. A scraper requests the same HTML document and searches that document for the pieces of information we need.

For this project, we do not need to understand every part of the target website. We only need to find the pieces of information that describe a greeting card.

For each card, our dataset needs two values:

  • title — the Russian title or description associated with the greeting card.
  • url — the URL of the greeting-card image.

That is enough for our application. Later, JavaScript can search the titles for category keywords and display the corresponding image URLs.

Why Use a CSV File?

CSV stands for Comma-Separated Values. It is a very simple text-based format for storing tabular data.

For our project, each row represents one greeting card. Conceptually, the file looks like this:

title,url
доброе утро,https://example.com/image1.jpg
с добрым утром,https://example.com/image2.jpg
счастливого понедельника,https://example.com/image3.jpg

The actual dataset will contain Russian titles and the real image URLs collected by the scraper.

CSV is particularly convenient for this project because we do not need a database server. The browser can request one static file, read its contents, and build the interface from it. This keeps the final application extremely simple.

Python Packages

The scraper uses several Python packages and standard-library modules:

import requests
from bs4 import BeautifulSoup
import time
import json
import csv
import os

The requests package is used to download HTML pages from the website.

BeautifulSoup, from the bs4 package, is used to parse the downloaded HTML and search for the elements containing the information we need.

The time module lets us pause between requests. This is important because the scraper should not immediately send hundreds of requests to the website one after another.

The json module is imported in the original script but is not actually used by the current implementation. It can therefore be removed, but we will leave the original code intact while explaining it.

The csv module writes the collected information into greetcards.csv.

The os module is used by the debug mode to check whether a previously downloaded HTML file exists.

Installing the Packages

Before running the scraper, Python needs the external packages requests and beautifulsoup4. The lxml parser used later by BeautifulSoup also needs to be installed.

pip install requests beautifulsoup4 lxml

The other modules in the script, such as time, csv, and os, are part of Python's standard library and do not need separate installation.

The Script Header

####################################
#
#    Script to scrape greetcards
#    from  https://otkrytki.top/
#
####################################

The first part is simply a comment. Python ignores everything beginning with #. It does not affect the scraper's behavior.

It is useful documentation, however. When we return to the project later, we immediately know what the script does and which website it was designed to collect data from.

Debug Mode

DEBUG = False

The script contains a debug mode. When DEBUG is False, the scraper downloads pages directly from the website.

When DEBUG is changed to True, the scraper can reuse previously saved HTML files instead of downloading the same pages again.

This is extremely useful while developing a scraper. HTML parsing is often the part that requires the most experimentation. If we already have a copy of the page saved locally, we can repeatedly modify the parsing code without repeatedly requesting the website.

The User-Agent

USER_AGENT = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/153.0.0.0 Safari/537.36"

When a normal browser requests a web page, it sends HTTP headers that provide information about the client. One of those headers is commonly called the User-Agent.

Our script sends a browser-like User-Agent when making requests. The value above identifies the client as a Chrome-like browser running on Windows.

The important part for this project is that the request is made with a recognizable HTTP User-Agent rather than relying on the default User-Agent of the Python requests library.

The Fetch Function

The most reusable part of the scraper is the fetch() function:

def fetch(url, filename):
    # Try extract data
    try:
        # Response holder
        response = None

        # Load HTML from file
        if DEBUG:
            # Parse HTML if exists
            if os.path.isfile(filename):
                with open(filename, encoding="utf-8") as f: response = f.read()
                print(f"Data loaded from {filename}")
            
            # Fetch HTML otherwise
            else:
                response = requests.get(url, headers={"user-agent": USER_AGENT}).text
                with open(filename, "w", encoding="utf-8") as f: f.write(response)
                print(f"Fetched data from {url}")

        # Load HTML from target URL
        else:
            response = requests.get(url, headers={"user-agent": USER_AGENT}).text
            print(f"Fetched data from {url}")
        
        # Parse HTML
        return BeautifulSoup(response, "lxml")

    # Print error on failure
    except Exception as e: print(repr(e));

The purpose of this function is simple: given a URL, obtain its HTML and return a BeautifulSoup object that we can search.

The second argument, filename, is used only by the debug mechanism. It tells the function where a downloaded HTML page can be stored locally.

Handling Errors

try:
    ...
except Exception as e: print(repr(e));

The network is not always reliable. A page might be unavailable, the internet connection might fail, or the website might return something unexpected. The try block allows the script to attempt the operation without immediately terminating the entire program when an exception occurs.

If something goes wrong, the except block prints the exception using repr(e).

This is useful during development because we can see the actual Python error instead of silently failing.

Why Keep the Response in a Variable?

response = None

The variable response will eventually contain the downloaded HTML as a string. Initializing it with None makes the intended flow explicit: at the beginning, there is no HTML yet, and one of the following branches will obtain it.

Debug Mode: Loading a Local Page

if DEBUG:
    if os.path.isfile(filename):
        with open(filename, encoding="utf-8") as f: response = f.read()
        print(f"Data loaded from {filename}")

When debug mode is enabled, the first question is whether the requested HTML file already exists.

os.path.isfile(filename) returns True if the specified path points to an existing file.

If the file exists, Python opens it using UTF-8 encoding and reads its entire contents into response.

This means the scraper does not need to contact the website again. We can work with a local copy of the page.

The encoding is important because the target website contains Russian text. UTF-8 can represent Cyrillic characters correctly, so we explicitly use encoding="utf-8".

Downloading the Page

If the local HTML file does not exist, the scraper downloads the page:

response = requests.get(
    url,
    headers={"user-agent": USER_AGENT}
).text

requests.get() sends an HTTP GET request to the specified URL.

The headers argument lets us send the User-Agent we defined earlier.

The .text property gives us the response body as text. In this case, that text is the HTML source code of the page.

Saving Downloaded HTML

with open(filename, "w", encoding="utf-8") as f:
    f.write(response)

When debug mode is enabled and the requested page has not been downloaded before, the scraper saves the HTML locally.

The "w" mode means that Python opens the file for writing. If the file already existed, it would be replaced.

Once the file has been saved, future debug runs can read the local copy instead of downloading it again.

Parsing HTML with BeautifulSoup

return BeautifulSoup(response, "lxml")

This is where the raw HTML becomes much easier to work with.

BeautifulSoup parses the HTML and builds an object representing its structure. Instead of manually searching through a huge string, we can ask BeautifulSoup to find particular tags, IDs, classes, attributes, and other elements.

The second argument, "lxml", tells BeautifulSoup which parser to use.

After this function returns, the caller receives a BeautifulSoup object rather than a plain HTML string.

Building the Greeting-Card Database

The main function responsible for collecting the dataset is:

def fetch_greetcards():
    ...

This function coordinates the entire scraping process. It starts at the website's main page, discovers the category URLs, determines how many pages each category contains, visits those pages, finds the greeting-card images, extracts their information, and writes each card to the CSV file.

Reporting Debug Mode

print(f"Debug mode is {"on" if DEBUG else "off"}")

The script begins by printing whether debug mode is enabled.

This uses a Python conditional expression inside an f-string. If DEBUG is true, the expression produces "on". Otherwise, it produces "off".

This is a small convenience, but it is useful when running the scraper because we immediately know whether pages will be downloaded or loaded from local files.

Starting at the Main Page

data = fetch("https://otkrytki.top/", "categories.html")

The scraper first downloads the site's main page.

The result is stored in data. Because fetch() returns a BeautifulSoup object, data can immediately be searched for HTML elements.

The filename categories.html is used only when debug mode is enabled. It gives us a local copy of the page containing the site's category menu.

Finding the Main Menu

categories = data.find(
    "ul",
    {"id": "primary-menu"}
).find_all("li")

Now we use the structure of the target website to locate its category menu.

The scraper looks for a <ul> element whose ID is primary-menu. Once that list is found, find_all("li") retrieves all of its list-item elements.

Conceptually, the HTML might look something like this:

<ul id="primary-menu">
    <li>
        <a href="https://otkrytki.top/category/morning/">
            Доброе утро
        </a>
    </li>
    <li>
        <a href="https://otkrytki.top/category/monday/">
            Понедельник
        </a>
    </li>
</ul>

We are not interested in the visible category text at this point. We primarily need the URLs because those URLs lead us to the pages containing the greeting cards.

Extracting Category URLs

category_urls = [
    i.find("a")["href"]
    for i in categories
    if "https" in i.find("a")["href"]
]

This list comprehension goes through every menu item and finds its <a> link.

The ["href"] expression retrieves the destination URL from the link.

The condition if "https" in ... filters the results so that only links containing an HTTPS URL are included.

The result is a Python list containing the category URLs that the scraper will visit.

Why Discover Categories Automatically?

We could manually write a list of category URLs into the script, but that would make the scraper dependent on a fixed set of categories.

By reading the website's menu, the script discovers the categories dynamically. If the site contains many categories, we do not need to type every URL manually.

This is a common scraping technique: first discover the site's navigation structure, then follow the links that lead to the content we need.

Looping Through Categories

for category in category_urls:
    ...

Now the scraper processes every discovered category one at a time.

At this point we have moved from the site's main navigation into the actual content collection stage.

Finding the Number of Pages

data = fetch(category, "pagination.html")

Before downloading all of the cards from a category, the script needs to know how many pages belong to that category.

It therefore downloads the category's first page and examines its pagination controls.

The result is again a BeautifulSoup object.

Reading Pagination

try:
    total_pages = max([
        int(i.text)
        for i in data.find_all("a", {"class": "page-numbers"})
        if i.text
    ])
except:
    total_pages = 1

The website uses links with the class page-numbers for pagination. The scraper finds all of those links.

For each link, i.text contains its visible text. The list comprehension keeps the non-empty values and converts them to integers.

For example, if the page contains links for pages 1, 2, 3, 4, and 5, the resulting list becomes:

[1, 2, 3, 4, 5]

The max() function then gives us 5, which becomes the total number of pages.

The try/except is used because some categories may not have pagination at all. If no usable page numbers can be found, the script assumes that the category has only one page.

Why Use One Page as the Default?

except:
    total_pages = 1

A category with only one page may not have a visible pagination control. In that situation, failure to find pagination does not necessarily mean something went wrong.

The fallback value of 1 lets the scraper continue and process the first category page.

This is a useful defensive programming technique: when a website does not provide optional information, use a sensible default rather than immediately stopping the entire scraping process.

Reporting the Page Count

print(f"Total pages: {total_pages}")

The scraper prints the number of pages found for the current category. This makes the progress visible in the terminal and is useful when collecting a large dataset.

Looping Through the Pages

for page in range(1, total_pages + 1):
    ...

Python's range() excludes its ending value. Therefore, range(1, total_pages + 1) generates every page number from 1 through total_pages.

Adding a Delay Between Requests

time.sleep(1)

Before requesting each page, the scraper waits for one second.

This is an important part of responsible scraping. A script can make HTTP requests much faster than a human using a browser. Without a delay, a large scraper could send a very large number of requests to the website in a short period of time.

The one-second delay slows the process down and reduces the request rate.

The exact delay is a project choice. In a real scraping project, the website's terms, robots.txt instructions, rate limits, and server behavior should also be considered. The goal is to collect the data without unnecessarily stressing the source website.

Building the Page URL

page_url = category + "page/" + str(page)

The scraper constructs the URL for each numbered page by combining the category URL with the pagination path and the current page number.

For example, if the category URL is something like:

https://otkrytki.top/category/morning/

the script may construct:

https://otkrytki.top/category/morning/page/2

The str(page) call converts the integer page number into text so that it can be concatenated with the strings around it.

Downloading the Page

data = fetch(page_url, str(page) + ".html")

The page is downloaded through the same fetch() function we already examined.

The second argument produces a filename such as 1.html, 2.html, or 3.html when debug mode is enabled.

This gives us another local copy of the page that can be reused during development.

Finding the Greeting Cards

greetcards = data.find_all(
    "img",
    {
        "class":
        "attachment-post-thumbnail size-post-thumbnail wp-post-image"
    }
)

Now we reach the most important part of the HTML parsing.

The scraper searches for <img> elements with a particular CSS class. According to the structure of the target website, these image elements represent the greeting-card images displayed on the page.

BeautifulSoup returns all matching image elements as a list.

For example, the HTML may contain an element conceptually similar to:

<img
    class="attachment-post-thumbnail size-post-thumbnail wp-post-image"
    title="Доброе утро"
    src="https://example.com/card.jpg"
>

The scraper does not need to download the image itself. It only needs to extract the information that identifies it.

Why Extract the Image URL Instead of the Image?

This is an important architectural decision for the project.

We store the image URL in the CSV instead of downloading every image and putting all of those image files into our project.

As a result, the final application can remain very small. The browser reads the URL from the CSV and requests the image directly when it needs to display it.

This means our repository contains the application and dataset, but not a huge collection of greeting-card image files.

Looping Through the Cards

for card in greetcards:
    ...

The page can contain multiple greeting cards, so the scraper processes each matching image separately.

For every image, we attempt to extract the title and image URL and then save those values into the CSV file.

Protecting Individual Cards with try/except

try:
    ...
except Exception as e:
    print(repr(e));

Notice that there is another error handler around the processing of each individual card.

This is useful because one malformed or unexpected image should not necessarily stop the entire scraping process.

If one card does not have the expected attributes, the script prints the error and continues with the next card.

Extracting the Card Data

features = {
    "title": card["title"].replace('"', ""),
    "url": card["src"]
}

We now create a Python dictionary containing the two pieces of information required by our application.

The title comes from the image element's title attribute.

The url comes from the image element's src attribute.

The dictionary therefore has exactly the same conceptual structure as one row in our CSV file.

Removing Double Quotes from Titles

card["title"].replace('"', "")

The scraper removes double-quote characters from the title.

This is done because the title will eventually be written into a CSV file, where quotes can have special meaning depending on the CSV representation.

The Python CSV module is capable of handling quoting correctly, so this replacement is not strictly required in every situation. In this particular scraper, however, it keeps the collected title values simpler.

Getting HTML Attributes

The syntax card["title"] is how BeautifulSoup allows us to retrieve an HTML attribute.

Similarly, card["src"] retrieves the image's source URL.

If the HTML contains:

<img title="Доброе утро" src="https://example.com/card.jpg">

then:

card["title"]

returns the title, while:

card["src"]

returns the image URL.

Writing to the CSV File

with open(
    "greetcards.csv",
    "a",
    newline="",
    encoding="utf-8"
) as f:
    csv_writer = csv.DictWriter(
        f,
        fieldnames=features.keys()
    )
    csv_writer.writerow(features)

This code opens the CSV file and appends one new row.

The filename is greetcards.csv. Because the Python scraper lives inside the data directory, the intended working directory for running the script is the same directory, so the resulting file is also created there.

The "a" mode means append. Instead of replacing the existing file, Python adds new content to the end.

newline="" is recommended when using Python's CSV module. It prevents unwanted blank lines from appearing in CSV files on some platforms.

encoding="utf-8" is essential because our titles contain Russian Cyrillic characters.

DictWriter

csv_writer = csv.DictWriter(
    f,
    fieldnames=features.keys()
)

csv.DictWriter is designed to write dictionaries into CSV rows.

Our dictionary contains the keys title and url, so those keys become the CSV column names.

The writer then knows how to map each dictionary value to the correct column.

Writing One Card

csv_writer.writerow(features)

This writes the dictionary as one row in the CSV file.

If the dictionary contains a title and URL, one corresponding record is appended to the dataset.

The important thing to notice is that the scraper writes each card immediately rather than first storing every card in a huge Python list. This means the CSV file is progressively built while the scraper runs.

Defining a function does not execute its contents. Python only runs the code inside fetch_greetcards() when we call it.

The Complete Scraper

Putting all of the pieces together, this is the scraper we use to build the dataset:

####################################
#
#    Script to scrape greetcards
#    from  https://otkrytki.top/
#
####################################

# Packages
import requests
from bs4 import BeautifulSoup
import time
import json
import csv
import os

# Debug mode:
DEBUG = False

# Web browser name
USER_AGENT = "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/153.0.0.0 Safari/537.36"

# Fetch data from target URL
def fetch(url, filename):
    # Try extract data
    try:
        # Response holder
        response = None

        # Load HTML from file
        if DEBUG:
            # Parse HTML if exists
            if os.path.isfile(filename):
                with open(filename, encoding="utf-8") as f: response = f.read()
                print(f"Data loaded from {filename}")
            
            # Fetch HTML otherwise
            else:
                response = requests.get(url, headers={"user-agent": USER_AGENT}).text
                with open(filename, "w", encoding="utf-8") as f: f.write(response)
                print(f"Fetched data from {url}")

        # Load HTML from target URL
        else:
            response = requests.get(url, headers={"user-agent": USER_AGENT}).text
            print(f"Fetched data from {url}")
        
        # Parse HTML
        return BeautifulSoup(response, "lxml")
    
    # Print error on failure
    except Exception as e: print(repr(e));

# Build greetcards database
def fetch_greetcards():
    # Print debug mode
    print(f"Debug mode is {"on" if DEBUG else "off"}")

    # Get category URLs
    data = fetch("https://otkrytki.top/", "categories.html")
    categories = data.find("ul", {"id": "primary-menu"}).find_all("li")
    category_urls = [i.find("a")["href"] for i in categories if "https" in i.find("a")["href"]]

    # Loop over category URLs
    for category in category_urls:
        # Get pagination data
        data = fetch(category, "pagination.html")

        # Get number of total pages
        try: total_pages = max([int(i.text) for i in data.find_all("a", {"class": "page-numbers"}) if i.text])
        except: total_pages = 1
        
        # Print total pages
        print(f"Total pages: {total_pages}")
        
        # Loop over page URLs
        for page in range(1, total_pages+1):
            # Delay between requests
            time.sleep(1)
            
            # Build page URL
            page_url = category + "page/" + str(page)
            
            # Get page data
            data = fetch(page_url, str(page) + ".html")

            # Get greetcards
            greetcards = data.find_all("img", {"class": "attachment-post-thumbnail size-post-thumbnail wp-post-image"})
            
            # Loop over greetcards
            for card in greetcards:
                # Attempt extracting greetcard data
                try:
                    # Extract features
                    features = {
                        "title": card["title"].replace('"', ""),
                        "url": card["src"]
                    }
                    
                    # Store greetcard to CSV
                    with open("greetcards.csv", "a", newline="", encoding="utf-8") as f:
                        csv_writer = csv.DictWriter(f, fieldnames=features.keys())
                        csv_writer.writerow(features)

                # Fallback on error
                except Exception as e: print(repr(e));

# Run script
fetch_greetcards()

Running the Scraper

Because greetcards.py is located inside the data directory, open a terminal in that directory and run:

python greetcards.py

If everything works correctly, the terminal will show messages indicating which pages are being downloaded and how many pages were found for each category.

The scraper may take some time to finish because it intentionally waits one second between page requests. This is expected. The purpose is to collect the dataset carefully rather than make the process as fast as possible.

The Resulting Dataset

After the scraper finishes, data/greetcards.csv contains the information collected from the website.

The important point is that the CSV is not the application itself. It is the application's data source.

Later, the browser application will request this file:

data/greetcards.csv

JavaScript will read the Russian titles and image URLs, search the titles for Russian keywords, and then create the visible greeting-card elements on the page.

The Dataset and the English Interface

There is an important translation detail in this project. The original greeting-card website is Russian, and the collected dataset remains Russian. The book, however, presents the application interface in English.

For example, a category displayed in the application may be called Good Morning, but its dataset keywords remain Russian:

{
    name: "Good Morning",
    keywords: [
        "добрым утром",
        "доброе утро"
    ]
}

This is intentional. We are translating the user interface, not translating the source dataset.

If we translated the keywords into English, the application would search for English words inside Russian titles and would not find the intended cards. The displayed category name can therefore be English while the search keywords remain Russian.

Why the Scraper Is Separate from the PWA

The scraper is a development and data-preparation tool. The PWA does not need Python, BeautifulSoup, or requests in order to display the finished dataset.

This gives us a clean separation:

Python scraper
        ↓
greetcards.csv
        ↓
JavaScript in index.html
        ↓
mobile interface
        ↓
user sees greeting cards

The Python program collects the data. The CSV stores the data. The browser application consumes the data.

This separation also means that we do not need a backend server for the finished application. Once the CSV has been generated, it can simply be placed in the project's data directory and served as a static file.

Why We Do Not Scrape from the Browser

It might seem natural to let JavaScript open the greeting-card website directly and collect the cards when the user opens the application. In practice, that would introduce several problems.

Browsers enforce security restrictions such as the same-origin policy and CORS. A page hosted on our GitHub Pages domain cannot automatically make arbitrary requests to another website unless that website explicitly allows the browser request.

There is also no reason for every user to repeat the same scraping operation. We can collect the dataset once, store it as a static CSV file, and let every user load the prepared data.

That makes the final application faster, simpler, and much easier to host.

Why We Keep the HTML Cache Files

The scraper's debug mode is more than a convenience. It gives us a way to develop against a snapshot of the website.

Suppose the website contains one thousand greeting cards. During development, repeatedly downloading the same pages just to test a small parsing change would create unnecessary network traffic and make development slower.

With DEBUG = True, the first run downloads the HTML files. Later runs can reuse those files.

This allows us to experiment with BeautifulSoup selectors locally. Once the parser works correctly, we can switch debug mode off and perform the real data collection.

A Note About Scraping and Website Changes

Web scrapers depend on the HTML structure of the website they scrape. Our code expects a menu with the ID primary-menu, pagination links with the class page-numbers, and greeting-card images with a particular CSS class.

If the website changes its HTML structure, one or more of these selectors may stop working.

This is a normal property of web scraping. The scraper is not communicating with a formal database API that guarantees a fixed schema. It is interpreting the current HTML structure of a website.

That is another reason why the dataset should be thought of as a prepared resource. We run the scraper when we need to refresh the collection, inspect the resulting CSV, and then use that static dataset in the application.

Why the Scraper Does Not Need to Run for Every User

The end user of our greeting-card PWA should never need to install Python or run the scraper.

The scraper is used by the developer to prepare greetcards.csv. Once that file exists, the PWA can simply load it.

In other words, scraping is part of the build process, not part of the application's runtime.

We now have the first major component of the project: a reproducible way to collect greeting-card data.

The Python script discovers categories, follows pagination, finds greeting-card images, extracts their Russian titles and image URLs, and writes those records into data/greetcards.csv.

The original website and dataset remain Russian. The English translation will happen in the application's user interface, not inside the dataset itself. This allows the application to present English category names while still searching the original Russian titles with Russian keywords.

Our project is therefore no longer just an empty HTML file. We have a real data source prepared for the application.

In the next chapter, we can return to index.html and build the interface that will consume this dataset. The HTML will define the structure, CSS will make it look like a mobile application, and JavaScript will finally load data/greetcards.csv and turn the collected records into actual greeting cards on the screen.
