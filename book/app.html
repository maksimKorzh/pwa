Chapter 6

Application Logic

So far, we have built the HTML structure, added the visual design with CSS, and set up a local HTTP server for development. The page can now look like an application, but it still does not actually do anything. In this chapter, we will add the JavaScript that turns the static interface into a working greeting-card application.

The original application is written in Russian, so the dataset and the search keywords remain Russian. In the book, however, the user-facing interface is translated into English to make the application easier to understand for an international reader. This means that category names shown on the screen can be English while the keywords used to search the Russian dataset remain Russian.

What JavaScript Will Do

Our JavaScript code connects all the parts of the application together. It loads the CSV file, converts its contents into JavaScript objects, removes duplicate cards, creates the category buttons, searches cards by category, chooses random cards, displays cards on the page, opens the card viewer, copies links, opens the device sharing menu, and scrolls the page back to the top.

All of this code can live inside the <script> element at the bottom of index.html. This keeps the project simple: HTML, CSS, and JavaScript are all available in one file.

Defining the Categories

We begin with an array containing the categories used by the application. Each category is represented by an object with a name and a list of keywords.

const categories = [
    { name: "Good Morning", keywords: ["утр"] },
    { name: "Good Night", keywords: ["ноч"] },
    { name: "I Love You", keywords: ["юблю", "скучаю"] },
    { name: "For a Friend", keywords: ["одруг", "енщин"] },
    { name: "Seasons", keywords: ["весна", "лето", "осень", "зима"] },
    { name: "Happy Birthday", keywords: ["ождения"] },
    { name: "Happy New Year", keywords: ["овым"] },
];

The name is what the user sees as a category button. The keywords are what the program searches for in the Russian card titles.

Notice that the keywords are not translated. For example, the English category name "Good Morning" still uses the Russian keyword "утр". This is intentional because the dataset itself contains Russian titles. We are translating the interface, not the database.

The keywords are also deliberately short fragments rather than complete phrases. For example, "утр" can match Russian words containing that sequence. This makes the category search less dependent on the exact grammatical form used in a card title.

Storing Application State

Next, we create two variables that will hold information while the application is running.

let allCards = [];
let selectedCard = null;

allCards starts as an empty array. After the CSV is loaded, it will contain all greeting cards available to the application.

selectedCard stores the card currently displayed in the modal window. It is initially null because no card has been selected yet.

Loading the CSV File

The first major task is loading our dataset. JavaScript provides the fetch() function for requesting files over HTTP.

async function loadCSV() {
    const response = await fetch("data/greetcards.csv");
    const text = await response.text();

    allCards = text
        .split("\n")
        .filter(x => x.trim())
        .map(line => {
            const comma = line.indexOf(",");

            return {
                title: line.slice(0, comma).trim(),
                url: line.slice(comma + 1).trim()
            };
        });

    allCards = [...new Map(
        allCards.map(card => [card.url, card])
    ).values()];

    createCategoryButtons();
    showRandomCards();
}

The function is marked async because loading a file takes time. The await keyword tells JavaScript to wait for the requested operation to finish before continuing.

First, fetch("data/greetcards.csv") requests the CSV file. Because our project is being served from the local HTTP server, the browser requests the file relative to the current page.

The next line converts the response into plain text. At this point, JavaScript has the complete CSV contents as one large string.

Turning CSV Lines into Objects

We then split the text into separate lines.

text.split("\n")

Empty lines are removed with filter().

.filter(x => x.trim())

Finally, map() converts every CSV line into a JavaScript object containing a title and an image URL.

{
    title: "...",
    url: "..."
}

The code finds the first comma with indexOf(","). Everything before that comma becomes the title, while everything after it becomes the image URL.

This is a deliberately simple CSV parser because our generated dataset has this very simple structure: one title followed by one URL on each line.

Removing Duplicate Cards

The source data can contain the same image more than once. We do not want duplicate cards in the application, so we remove duplicates based on the image URL.

allCards = [...new Map(
    allCards.map(card => [card.url, card])
).values()];

This is a compact JavaScript technique that uses a Map. A Map stores values using keys. Here, the image URL is used as the key.

If the same URL appears more than once, the later entry replaces the previous entry. Calling values() gives us the remaining card objects, and the spread operator ... converts them back into an array.

The result is that every image URL appears only once in allCards.

Starting the Application

After the CSV has been loaded and cleaned, two functions are called.

createCategoryButtons();
showRandomCards();

The first creates the category buttons. The second displays an initial selection of cards so the application is not empty when it opens.

Showing Random Cards

The home view displays one random card for each category.

function showRandomCards() {
    const randomCards = [];
    const usedUrls = new Set();

    categories.forEach(category => {
        const matches = allCards.filter(card => {
            const title = card.title.toLowerCase();

            return category.keywords.some(keyword =>
                title.includes(keyword.toLowerCase())
            ) && !usedUrls.has(card.url);
        });

        if (matches.length > 0) {
            const randomCard =
                matches[Math.floor(Math.random() * matches.length)];

            randomCards.push(randomCard);
            usedUrls.add(randomCard.url);
        }
    });

    renderCards(randomCards);
    scrollToTop();
}

We first create an empty array called randomCards. This will contain the cards that are eventually displayed.

We also create a Set called usedUrls. A set is useful when we need to keep track of unique values. Here it prevents the same image from being selected for two different categories.

The forEach() method then processes every category.

For each category, filter() searches through all available cards. The card title is converted to lowercase so that the search is not affected by capitalization.

const title = card.title.toLowerCase();

The some() method checks whether at least one keyword occurs in the title.

category.keywords.some(keyword =>
    title.includes(keyword.toLowerCase())
)

The second condition checks that the card has not already been selected.

!usedUrls.has(card.url)

If matching cards exist, JavaScript chooses one at random.

const randomCard = matches[Math.floor(Math.random() * matches.length)];

The selected card is added to randomCards, and its URL is added to usedUrls so it cannot be selected again for another category.

Finally, the resulting cards are passed to renderCards(), which creates the HTML elements that the user sees.

Creating the Category Buttons

The category buttons are created dynamically with JavaScript instead of writing every button manually in HTML.

function createCategoryButtons() {
    const container = document.getElementById("categories");

    categories.forEach(cat => {
        const btn = document.createElement("button");

        btn.className = "category-btn";
        btn.innerText = cat.name;

        btn.onclick = () => {
            showCategory(cat);
            scrollToTop();
        };

        container.appendChild(btn);
    });
}

document.getElementById("categories") finds the HTML element that will contain the buttons.

For every category, document.createElement("button") creates a new button element.

We then assign the CSS class and the text displayed on the button.

btn.className = "category-btn";
btn.innerText = cat.name;

The important part is the onclick handler. When the user taps a category button, the application calls showCategory(cat).

Finally, appendChild() inserts the newly created button into the categories container.

Searching a Category

The showCategory() function performs the actual category search.

function showCategory(category) {
    let found = allCards.filter(card => {
        const title = card.title.toLowerCase();

        return category.keywords.some(keyword =>
            title.includes(keyword.toLowerCase())
        );
    });

    found = shuffle(found).slice(0, 10);

    renderCards(found);
    scrollToTop();
}

The search works in much the same way as the random home view. We check every card and keep the cards whose titles contain at least one of the category's Russian keywords.

After finding the matches, we shuffle them and keep only the first ten.

found = shuffle(found).slice(0, 10);

This gives the user a maximum of ten randomly ordered cards whenever a category is selected.

Rendering Cards on the Page

Finding cards is not enough. We need to turn the JavaScript objects into actual HTML elements.

function renderCards(cards) {
    const container = document.getElementById("cards");
    container.innerHTML = "";

    cards.forEach(card => {
        const div = document.createElement("div");
        div.className = "card";

        div.innerHTML = `
            <img loading="lazy" src="${card.url}">
            <div class="card-title">
                ${card.title}
            </div>
        `;

        div.onclick = () => openModal(card);
        container.appendChild(div);
    });
}

First, we find the cards container and clear its previous contents.

container.innerHTML = "";

This is important because changing categories should replace the old cards rather than append new cards underneath them.

For every card, we create a new div, give it the card class, and build its contents with a template literal.

The image uses loading="lazy". This tells the browser that images can be loaded as they become necessary instead of immediately loading every image at once.

The card also receives a click handler:

div.onclick = () => openModal(card);

Clicking or tapping the card therefore opens the modal containing the selected greeting card.

Shuffling the Results

The application uses a small helper function to create a new randomly ordered array.

function shuffle(arr) {
    return [...arr].sort(() => Math.random() - 0.5);
}

The spread operator creates a copy of the original array, so the original array is not modified directly.

The sort() callback uses Math.random() to change the order of the elements. For this application, the simple approach is sufficient because we only need a varied selection of greeting cards rather than a cryptographically secure randomization algorithm.

Opening the Modal

When a card is clicked, the application opens the modal viewer.

function openModal(card) {
    selectedCard = card;

    document.getElementById("modalImg").src = card.url;

    document.getElementById("modal")
        .classList.remove("hidden");
}

The selected card is saved in selectedCard. This is important because the Share and Copy buttons need to know which card the user is currently viewing.

Next, the image URL is assigned to the modal image element. Finally, the hidden CSS class is removed, making the modal visible.

Closing the Modal

The Close button simply adds the hidden class back to the modal.

document.getElementById("closeBtn").onclick = () => {
    document.getElementById("modal").classList.add("hidden");
};

This is a good example of how CSS and JavaScript work together. CSS defines what the hidden class means, while JavaScript decides when that class should be added or removed.

Copying the Card Link

The Copy Link button needs to work in more than one browser environment. Modern browsers provide the Clipboard API, but it is subject to security requirements.

document.getElementById("copyBtn").onclick = async () => {
    try {
        if (navigator.clipboard && window.isSecureContext) {
            await navigator.clipboard.writeText(selectedCard.url);
            alert("Link copied");
            return;
        }

        const textarea = document.createElement("textarea");
        textarea.value = selectedCard.url;
        textarea.style.position = "fixed";
        textarea.style.opacity = "0";

        document.body.appendChild(textarea);
        textarea.focus();
        textarea.select();

        const success = document.execCommand("copy");

        document.body.removeChild(textarea);

        if (success) {
            alert("Link copied");
        } else {
            alert("Could not copy the link");
        }
    } catch (error) {
        console.error("Copy error:", error);
        alert("Could not copy the link");
    }
};

The first attempt uses navigator.clipboard.writeText(). The code checks both that the Clipboard API exists and that the page is running in a secure context.

If that modern method is not available, the code creates a temporary invisible textarea, selects its contents, and uses document.execCommand("copy") as a fallback.

The try...catch structure prevents an unexpected browser error from stopping the rest of the application.

Clipboard and sharing features are affected by browser security rules. This is one of the reasons the application should be tested through the development HTTP server instead of opening index.html directly with a file:// URL. Final sharing tests should be performed after deploying the application to GitHub Pages over HTTPS.

The More Cards Button

The main random button is connected to the same showRandomCards() function used when the application first loads.

document.getElementById("randomBtn").onclick = () => {
    showRandomCards();
    scrollToTop();
};

Every time the user presses the button, the application creates another random selection.

Sharing a Card

The Share button uses the browser's Web Share API when it is available.

document.getElementById("shareBtn").onclick = async () => {
    try {
        if (navigator.share) {
            await navigator.share({
                title: selectedCard.title,
                url: selectedCard.url
            });
            return;
        }

        await navigator.clipboard.writeText(selectedCard.url);
        alert("Link copied");
    } catch (error) {
        console.error("Share error:", error);

        if (error.name === "AbortError") {
            return;
        }

        alert("Could not open the sharing menu");
    }
};

If navigator.share exists, the browser opens its native sharing interface. On a mobile device, this can allow the user to choose an application such as WhatsApp or another installed messenger.

If Web Share is not available, the code falls back to copying the URL to the clipboard.

The AbortError check is useful because a user can open the sharing menu and then cancel it. Cancelling the share is not really an application error, so we simply return without showing an error message.

Scrolling Back to the Top

After changing the displayed cards, the application scrolls back to the beginning of the page.

function scrollToTop() {
    window.scrollTo({
        top: 0,
        behavior: "smooth"
    });
}

window.scrollTo() changes the page scroll position. Setting top to 0 means the top of the page, while behavior: "smooth" makes the movement animated instead of instant.

Starting the Application

At the very end of the script, we call the function that loads the dataset.

loadCSV();

This single call starts the application's JavaScript flow. The browser loads the CSV, converts it into objects, removes duplicates, creates the category buttons, and displays the initial cards.

The overall flow can now be summarized as:

loadCSV()
    ↓
fetch CSV
    ↓
convert CSV to JavaScript objects
    ↓
remove duplicate URLs
    ↓

How the Pieces Work Together

At this point, the application has a complete client-side data flow. The Python scraper created the dataset before the application runs. The CSV file provides the data. JavaScript loads and processes that data in the browser. HTML provides the elements that JavaScript manipulates, and CSS controls how those elements look.

There is no database and no application backend. The browser performs the searching, filtering, random selection, rendering, copying, and sharing itself.

This architecture is intentionally simple. The greeting-card images are not downloaded by the JavaScript application and stored on our server. The CSV contains their online URLs, and the browser loads the images from those URLs when they are displayed.

One Important Limitation of the CSV Parser

Our CSV parser is intentionally minimal. It assumes that the first comma separates the title from the URL. A more general CSV parser would need to correctly handle quoted fields, commas inside text, escaped quotes, and other CSV rules.

For this project, the dataset generated by our scraper follows a simple predictable format, so a small parser keeps the application easier to understand.

The Application Is Now Interactive

With this JavaScript in place, the interface is no longer just a collection of HTML elements. The category buttons are generated from data, the CSV becomes usable application data, cards are searched and randomized, and the modal can display a selected card.

We also have browser integration for copying links and sharing them through the device's native sharing interface where supported.

The important idea is that JavaScript is acting as the connection between the data and the interface. It reads the dataset, makes decisions about which cards to show, and updates the HTML whenever the user interacts with the application.
